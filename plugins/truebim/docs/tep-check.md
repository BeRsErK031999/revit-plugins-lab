# Проверка ТЭП

Команда **TrueBIM → АР → Проверка ТЭП** читает помещения, зоны и машиноместа
активного проекта и загруженных связей. Модель не изменяется. Целевая версия —
Revit 2024 (.NET Framework 4.8); интеграционная проверка выполняется на Revit 2024.3.5.

## Установка пакета

Распакуйте архив `TrueBIM-TEP-Revit2024-*.zip` и запустите `Install.ps1` из
распакованной папки в PowerShell. Скрипт копирует сборку в отдельный каталог
`%APPDATA%\TrueBIM\2024\TEP-*` и переключает пользовательский `TrueBIM.addin`.
Если манифест уже существует, рядом сохраняется его резервная копия.
Затем перезапустите Revit 2024. Для отката восстановите содержимое резервной
копии в `TrueBIM.addin` и снова перезапустите Revit.

Пакет содержит полную сборку TrueBIM из текущего рабочего каталога, включая
остальные модули. Проверки этой задачи относятся к модулю ТЭП; полный регресс
остальных модулей не выполнялся. Установка пакета автоматически не запускалась.

## Работа с проектом D105

1. Откройте стилобат с загруженными Б1, Б2 и КР. Проверьте пути связей:
   в переданном комплекте имена файлов имеют суффикс `_для ТЭП`, а сохранённые
   ссылки ожидают имена без этого суффикса.
2. Выберите файлы помещений Б1, стилобата и Б2. Для зон выберите Б2:
   в переданной версии этого файла есть спецификации полного пятна застройки
   и сечения +4,500. Используется только один источник зон.
3. Проверьте названия трёх спецификаций и нажмите **Прочитать модели**.
4. Во вкладках источников проверьте флаги учёта, части здания, категории,
   жилые/холодные помещения, коэффициенты, состав офисных площадей и этажей.
   Поиск работает по имени, ID, группе, категории, части и документу.
5. Нажмите **Рассчитать**. Пока классификация не подтверждена, результат имеет
   статус «Предварительно». Подтверждение не снимает ошибки исходных данных.
6. Выберите исходный `ТЭП.xlsx`, затем **Экспорт Excel**. Укажите новое имя файла.

В стилобате помещения с обозначением квартиры `1К`–`4К` первоначально исключаются.
В файлах башен используются помещения с параметром `• Секция` соответственно `1`
и `2`. Копии помещений с одним `UniqueId` в стилобате и выбранной башне исключаются
из стилобата с записью в диагностике. Остальные помещения стилобата, включая
помещения под башнями, первоначально относятся к стилобату. Принадлежность можно
исправить в таблице источников. Этажи с различным назначением нельзя определять
только по числу объектов Level.

## Расчёт

Поддерживаются 37 строк исходного шаблона, строки Excel 2–38, в колонках
Б1, Стилобат, Б2 и Итог.

| Показатели | Источник и операция |
|---|---|
| Застройка, сечение +4,500 | Суммы площадей зон из двух отдельных спецификаций |
| Площадь здания | Зоны выше и ниже нуля, эксплуатируемая кровля |
| Объём | Площадь зоны × `Зона Высота (TB)`; только зоны с флагом «Объём» |
| Этажность, количество этажей | Уникальные уровни зон с соответствующими флагами |
| Квартиры | `• Группа помещений • Номер` и `• Группа помещений • Тип` |
| Жилые/холодные площади | `• Помещение • Тип`, коэффициент и проверяемые флаги |
| Кладовые, МОП, технические, коммерция, паркинг | Назначение помещения и проверяемая классификация |
| Расчётная/полезная офисов | Коммерческие помещения и МОП коммерции с соответствующими флагами |
| Машиноместа | Экземпляры категории «Парковка» внутри помещений паркинга выбранного файла стилобата |
| Жильцы | Площадь квартир без холодных помещений / подтверждённая удельная площадь |
| Сотрудники | Площадь помещений с флагом «Рабочие места» / подтверждённая удельная площадь |

Площади читаются из геометрического `Room.Area`/`Area.Area`, высота — из числового
параметра зоны. Повторяющиеся параметры итоговой площади квартиры не суммируются.
Вычисления выполняются без промежуточного округления. Площади отображаются
с одним десятичным знаком. Количества квартир, кладовых, этажей и мест — целые.
Расчётные люди сохраняются без округления до целого; правила такого округления
должны быть определены в проектном основании.

Машиноместо относится к паркингу, если его точка вставки находится в помещении
категории паркинга; дополнительно проверяется точка на 0,5 фута выше, чтобы
учесть вставку на границе пола. Внешние места остаются в источниках с выключенным
флагом учёта. При отсутствии точки или корректных помещений паркинга выдаётся
ошибка, а не нулевой результат. В переданном комплекте этот отбор даёт 52 места.

Итог этажей — строка **Б1-Стилобат-Б2**, например `13-2-21`; этажи не складываются.
Начиная с версии 0.2.33 помещения с нулевой площадью автоматически пропускаются
в суммах и количествах. Расчёт продолжается по остальным помещениям, а в
диагностике сохраняются документ, ID и имя каждого пропущенного помещения.
Затронутые результаты и общий итог имеют статус «Неполный расчёт» и знак `*`;
в Excel соответствующие ячейки дополнительно выделяются жёлтым. Подтверждение
классификации не снимает это предупреждение. В расчёт количества квартир и
коммерческих блоков входят только группы, представленные оставшимися помещениями.
Если все помещения показателя имеют нулевую площадь, отображается `0 *`.
Независимые показатели предупреждения не получают.

Отсутствие необходимого документа или зон, некорректная ненулевая площадь,
неопределённый тип учитываемого помещения и другие ошибки по-прежнему могут
означать «Нет данных». Нулевые зоны автоматически не пропускаются.

## Нормативная основа и проверяемые решения

На 20.10.2026 официальные карточки Росстандарта содержат:

- [СП 54.13330.2022](https://protect.gost.ru/sp/details/c8b00dd7-7c13-4f17-ac0c-d9cf70311263),
  изменения № 1–2;
- [СП 118.13330.2022](https://protect.gost.ru/sp/details/ced01945-2f53-47c9-bdb8-4875c2b9800e),
  изменения № 1–5.

Применяются правила подсчёта приложения А. Плагин суммирует заданные проектом
контуры зон; он не строит заново наружный контур здания, не доказывает соответствие
каждого контура нормативному определению и не объединяет геометрически
пересекающиеся зоны. Наличие зон внутри спецификации само по себе не подтверждает
их правильность. Границы площади и строительного объёма могут различаться.
Открытые террасы, кровли, технические этажи, цоколь и многосветные пространства
требуют проверки. У зон кровли предварительно выключены объём и учёт этажей;
у открытой террасы — объём.

Для офисов флаги расчётной/полезной площади предварительно назначаются по имени.
Проверьте исключения приложения А СП 118 для лестниц, шахт, коммуникационных
пространств и оборудования. Флаг рабочих мест первоначально установлен
только для помещений с именем «Офис».

Удельные значения 40 и 6 перенесены из исходной таблицы и **не являются
автоматическим нормативным заключением** для премиального жилья в Бийске.
Расчёт людей включается после ввода и подтверждения применимого основания.
Исходная таблица делит всю коммерческую площадь без МОП на 6; плагин отдельно
позволяет выбрать площадь рабочих помещений. Класс «премиум» не приравнивается
автоматически к региональному классу жилья. Применимость местных нормативов
и параметров конкретного проекта должна быть установлена в основании.

## Excel и профиль

Исходный файл не изменяется. В копию добавляются:

- **Расчёт ТЭП** — таблица исходной формы с вычисленными значениями;
- **Сверка** — исходное значение, формула, расчёт, разница, статус и объяснение;
- **Диагностика** — ошибки, исключения и арифметические несогласованности исходника;
- **Источники** — все прочитанные элементы, включая исключённые;
- **Связи расчёта** — полный перечень связей «ячейка → ключ источника».

Шапка C1:F1 и названия всех 37 строк проверяются перед экспортом. Иной шаблон
не заполняется молча. Исходные формулы и оформление сохраняются; новый расчёт
записывается числами полной точности с форматом `0.0`. Знак `*` для неполных
результатов добавляется числовым форматом, поэтому ячейки остаются числовыми.
Сверка использует сохранённый кэш исходных формул: перед запуском пересчитайте
и сохраните оригинал в Excel. Движок расчёта Excel не запускается.

Профиль JSON хранит решения классификации по ключу «путь документа + UniqueId».
После повторного чтения площадей и высот профиль можно загрузить вручную.
Изменения геометрии, ошибки источника и подтверждение нормативного основания
из профиля не подменяют текущую модель. После перемещения/переименования файлов
ключи могут не совпасть; число сопоставленных строк показывается в окне.

## Проверки разработчика

```powershell
.\tools\.dotnet\dotnet.exe build plugins/truebim/src/TrueBIM.App/TrueBIM.App.csproj -c Release -f net48 -p:RevitVersion=2024
.\tools\.dotnet\dotnet.exe test plugins/truebim/tests/TrueBIM.App.Tests/TrueBIM.App.Tests.csproj -c Release -p:RevitVersion=2025 --filter "FullyQualifiedName~Modules.Tep|FullyQualifiedName~AppRibbonButtonDefinitionTests"
```

`tests/TrueBIM.Revit.TepHarness` компилирует те же исходники расчёта и коллектора
под Revit 2024. Проверочный процесс открывает отделённую копию, читает связанные
документы, формирует снимок, расчёт и XLSX, закрывает документ без сохранения.
Он не подтверждает окна безопасности и не исправляет пути связей исходной модели.
Переменные запуска: `TRUEBIM_TEP_TEST_MODEL`, `TRUEBIM_TEP_TEST_OUTPUT`,
`TRUEBIM_TEP_TEST_TEMPLATE`. Для тестирования необходим отдельный временный
манифест надстройки, удаляемый после завершения.
