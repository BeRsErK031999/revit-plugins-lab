# Проверка заполнятора арматуры

Дата: 2026-10-21. Выпуск TrueBIM 0.2.38. Целевая версия задачи: Revit 2019.

## Выбор вложенных стержней в 0.2.38

- Добавлены галочки, фильтр по семейству/типу, сортировка и массовый выбор показанных строк. В подтверждение и запись передаются только отмеченные ID текущего фильтра.
- 42 автоматические проверки успешно: 36 проверок ленты и 6 проверок области выбора (прямые/хомуты, исключение неотмеченных и скрытых строк, сохранение выбора, различение типов с одинаковым названием и устранение дублей).
- Отдельно проверено окно WPF на макетных строках без запуска Revit: галочки внутри таблицы, двусторонняя привязка, смена параметра и фильтра, массовый выбор. Это проверка интерфейса и области выбора, а не запись в RVT.
- Дополнительные проверки через Revit по указанию пользователя не выполнялись. Предыдущие ограничения проверки записи приведены ниже.
- Выпуск собран в отдельной рабочей копии от `895bd2e` с изменениями заполнятора; параллельные незавершённые изменения ведомости отделки не включены.

## Проверки записи и сборки

- Сборка полной TrueBIM.App против Revit API 2019 (`19.0.0.0`, reference package Nice3point.Revit.Api 2019.2.1): успешно, без предупреждений и ошибок.
- Сборки общего установщика для Revit 2019–2026: успешно. Для 2021 есть предупреждения об устаревшем API в существующем модуле IsoFieldRebar; ошибок сборки нет.
- Проверки ленты: 36/36 успешно.
- Первичная диагностика копии предоставленной модели в Revit 2022: у шести видов вложенных арматурных семейств проверено по 30 текстовых параметров с успешной записью и чтением после регенерации, с откатом каждой транзакции. Параметры только для чтения отвергаются Revit. Полный перебор всех параметров всех семейств остановлен после получения этих результатов; это не полный регрессионный прогон.
- Исходный файл имеет формат 2019. SHA-256 исходника до и после диагностики: `3BFFA07BB617405C416B89423938CACB6365AA2AD2AD06ABFF8F03D8BB0C9603`.
- Проверка сервиса записи на копии реальной модели в Revit 2022: **4 из 5 сценариев успешно**. Подтверждены запись в выбранный вложенный стержень без изменения соседей и родителя, повторная запись и режим «только пустые» для текста, разворачивание родителя и устранение дублей, отказ от записи недоступного параметра, сохранение принадлежности `RebarInSystem` системе и значений соседних стержней. Изменения тестовых сценариев откатывались.
- Пятый сценарий обнаружил ошибку незаданного числового параметра: его исходный ноль ошибочно считался уже записанным. Исправлено для Integer и Double: проверка совпадения теперь требует `HasValue`. Добавлены проверки явной записи нуля и его сохранения в режиме «только пустые». **Повторный прогон в Revit остановлен по указанию пользователя до получения результата; исправление нуля в Revit после изменения не подтверждено.** Все восемь сборок после исправления и 36 проверок ленты прошли.
- При открытии копии в 2022 Revit сообщил о предупреждениях обновления модели (включая старые размерные зависимости) и отсутствующей сторонней надстройке `UpdaterRevitLinks`. Эти особенности обновления ограничивают перенос результатов на 2019.
- EXE подготовлен через Inno Setup. Установка EXE в рабочий профиль пользователя не выполнялась. ZIP-установщик проверяется в отдельной тестовой папке, включая повторную установку и резервную копию предыдущего манифеста.

Revit 2019 на компьютере не установлен. Проверки в работающем Revit 2019, сохранение/повторное открытие результата и ручное выделение строк спецификации не выполнялись. Проверка сервиса на копии в Revit 2022 не подменяет эти проверки. По последнему указанию пользователя дополнительные проверки через Revit прекращены. Исходная модель не обновлялась и не сохранялась; её SHA-256 после остановки совпал с исходным.

Локальный отчёт первого прогона: `plugins/truebim/test-results/rebar-fill/580d9ea850ff4261ac3b10097c43f6f3/report.json`. Повторный прогон: каталог `839bcec59876489e9c6e6bf13f8f23df`, итогового отчёта нет. Эти временные каталоги не входят в поставку.

Для сборки 2019 также исправлена обнаруженная несовместимость существующей команды разбиения арматуры: отсутствующий в API 2019 метод дополнительных ссылок мультиарматурной аннотации больше не вызывается. При необходимости сохранить такую аннотацию в 2019 операция разбиения явно отменяется; остальные версии сохраняют прежнее поведение.
