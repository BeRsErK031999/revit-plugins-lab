# Сравнение ведомостей отделки — 16.09.2026

Статус: данные обеих ведомостей сопоставлены. Исправление высоты многострочных ячеек подтверждено экспортом временной копии из Revit. Расчёт площадей не менялся: шесть общих пропусков отмечены отдельно, поскольку эталон их также не учитывает.

## Источник и сохранность модели

Проверена открытая модель `D085_П_АР_ALL_rvt23_тест_Отделки_отсоединено`, Revit 2023.1. Считаны именно две указанные пользователем ведомости:

- Эталон: `Помещения • Ведомость отделки помещений`, ID 3142437.
- Плагин: `Помещения • Ведомость отделки помещений 12357756`, ID 3147937.

Обе ведомости являются статическими снимками TrueBIM. Эталон содержит 19 групп, новая ведомость — 30, обе охватывают 54 помещения. Создавались только временные листы для выгрузки PNG; вся группа транзакций отменена. Исходная модель не сохранена, существующие ведомости и параметры не изменены. Модель уже имела несохранённые изменения до аудита.

## Что подтверждено

- Все 30 строк новой ведомости совпадают с повторным расчётом текущей модели, включая многострочные значения.
- 520 стен, 52 пола и 114 потолков учтены по полной системной площади `HOST_AREA_COMPUTED`. Все 686 значений совпали с параметрами элементов; повторного учёта нет.
- Для всех 166 учтённых полов и потолков отдельная проверка контуров с сеткой около 10 см подтвердила помещение с наибольшим перекрытием. Это независимая приближённая проверка принадлежности; опубликованные площади взяты непосредственно из Revit, а не из этой сетки.
- В новой ведомости выбран параметр «Имя типа». В эталоне описания соответствуют параметру типа «• Состав». Это объясняет различия текста и части группировки; выбранная настройка соблюдена.

По уточнению пользователя от 17.09.2026 состав из эталона принят требуемым
источником текста. В версии 0.2.21 добавлена
[замена сохранённого источника «Имя типа» на состав](finish-schedule-composition-source-2026-09-17.md).
Это последующее изменение; результаты проверки 16.09 не подтверждают его работу.

- Увеличение площадей стен и большинства полов подтверждается полными площадями элементов. Подгонять новые суммы к старым не следует.

## Элементы, действительно пересекающие несколько помещений

## Отображение на листе

На PNG, экспортированном Revit, обнаружено обрезание текста и площадей в статических ячейках. Например, в помещении 101 в данных есть площади потолков 78,01 и 179,93 м², но второе значение на листе заменяется многоточием. Высота строки 12,52 мм недостаточна. У помещения 210 также обрезаны последние строки пола. Причина — измерение текста WPF по номинальному размеру без учёта метрик шрифта. Исправление учитывает отношение высоты заглавных букв к размеру шрифта, автоматические переносы и отступы. На повторном экспорте все длинные описания и числовые значения видны полностью.

Аудит `SnapshotLayoutAudit` сравнил временные копии с высотами ×1,5 и ×2 и измерения нативного `TextNote`. Увеличения ×1,5 недостаточно. В `layout-02` проверен исправленный расчёт по метрикам установленного шрифта GOST Common; результат экспортирован из Revit и просмотрен. Все временные изменения отменены.

## Файлы проверки

Выгрузки и изображения находятся в исключённом из Git каталоге `test-results/finish-model/comparison-01/`; проверки высоты — в `layout-01/` и `layout-02/`.

- `report.json` — исходная выгрузка двух таблиц, параметров, контуров и результатов расчёта.
- `report.json.result.json` — подтверждение успешного экспорта и отката временных листов.
- `group-differences.json` — сверка по одинаковым группам помещений.
- `independent-slab-overlaps.json` — независимая проверка принадлежности полов и потолков.
- PNG двух ведомостей — фактический вывод Revit на лист.
