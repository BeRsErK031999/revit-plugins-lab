# TrueBIM Parameter Audit

## Назначение

Команда `Проверка параметров` на панели `Проверка модели` выполняет read-only контроль
элементов текущего RVT-проекта по правилам из CSV или XLSX. Пользователь вручную выбирает
таблицу, проверяет её структуру, при необходимости включает загруженные RVT-связи и получает
сводную таблицу ошибок.

Инструмент не создаёт параметры, не заполняет значения и не открывает транзакцию Revit.

Кнопка `Методичка` в основном окне открывает встроенную пошаговую инструкцию по матрице,
отбору элементов, правилам заполненности, расшифровке ошибок и приёмке.

## Область первого релиза

- текущий проект целиком;
- загруженные RVT-связи — только при включённом флажке;
- параметры экземпляров и типов;
- shared parameters по GUID;
- встроенные параметры по имени `BuiltInParameter` или его числовому значению;
- остальные параметры по имени с явным предупреждением о возможной неоднозначности;
- обязательность, ожидаемое значение, список допустимых значений, регулярное выражение,
  минимум и максимум;
- CSV-экспорт только найденных ошибок и предупреждений.

Семейства RFA отдельно не открываются: проверяются элементы и типы, уже доступные в RVT.

## Основной матричный формат

Исходную матрицу можно выбирать напрямую в формате XLSX: используется первый лист книги.
Перед запуском нужно сохранить изменения в Excel, но закрывать книгу не требуется.

Матрица читается следующим образом:

- `A1` — имя параметра, по значению которого выбираются элементы, например `Описание`;
- `A2`, `A3` и далее — значения параметра отбора, например `Стены, перегородки`, `Двери`;
- `B1`, `C1` и далее — имена параметров, заполненность которых нужно проверить;
- `+` на пересечении строки и колонки — параметр обязателен для этой группы элементов;
- пустая ячейка — этот параметр для группы не проверяется.

Пример:

| Описание | ADSK_Номер корпуса | ADSK_Этаж | ADSK_Наименование |
|---|---:|---:|---:|
| Стены, перегородки | + | + | + |
| Двери | + | + |  |
| Ограждения | + |  | + |

Категория Revit в матричном формате не используется. TrueBIM рассматривает экземпляры разных
категорий и оставляет только те, у которых параметр из `A1` равен значению из колонки `A`.
Сравнение выполняется без учёта регистра. Сначала параметр ищется у экземпляра; если его нет —
у типа элемента. Такое же резервное чтение типа применяется к проверяемому параметру.

CSV может иметь разделитель `;`, `,` или табуляцию. Поддерживаются UTF-8, UTF-16 и Windows-1251,
который часто создаёт русская версия Excel. XLSX и CSV открываются с совместным доступом, поэтому
сохранённый файл можно проверять, пока он открыт в Excel.

## Расширенный построчный формат

Для проверок по категории, GUID, BuiltInParameter, допустимым значениям, регулярному выражению
или диапазону сохраняется расширенный формат. Заголовки поддерживаются на английском и русском.

| Колонка | Обязательность | Назначение |
|---|---:|---|
| `RuleId` | нет | Стабильный код правила; при пустом значении создаётся `RULE_<строка>` |
| `Enabled` | нет | `true/false`, `да/нет`, `1/0`; по умолчанию `true` |
| `Category` | да | Локализованное имя категории Revit или wildcard `*`/`?` |
| `Family` | нет | Имя семейства или wildcard; по умолчанию `*` |
| `Type` | нет | Имя типа или wildcard; по умолчанию `*` |
| `ParameterName` | условно | Имя параметра и подпись в отчёте |
| `ParameterGuid` | условно | GUID shared parameter; имеет приоритет над именем |
| `BuiltInParameter` | условно | Например `ALL_MODEL_MARK`; имеет приоритет над именем |
| `Scope` | нет | `Instance/Экземпляр` или `Type/Тип`; по умолчанию `Instance` |
| `Required` | нет | Требовать наличие и непустое значение; по умолчанию `true` |
| `ExpectedValue` | нет | Единственное ожидаемое значение |
| `AllowedValues` | нет | Допустимые значения через `|`, например `EI30|EI60` |
| `Regex` | нет | Регулярное выражение .NET для проверки строки |
| `Min` | нет | Минимальное числовое значение |
| `Max` | нет | Максимальное числовое значение |
| `CaseSensitive` | нет | Учитывать регистр при сравнении строк; по умолчанию `false` |
| `Severity` | нет | `Error/Ошибка` или `Warning/Предупреждение` |
| `Message` | нет | Пояснение заказчика, добавляемое к технической причине ошибки |

В строке должен быть указан хотя бы один идентификатор параметра: `ParameterGuid`,
`BuiltInParameter` или `ParameterName`. Одновременное указание GUID и BuiltInParameter
запрещено. `ParameterName` можно оставить рядом с GUID/BuiltInParameter как понятную подпись.

## Правила заполненности и сравнения

- пустая строка и строка только из пробелов считаются незаполненными;
- числовой `0` считается заполненным;
- логическое `Нет/False` считается заполненным;
- значения `-`, `Н/Д` и другие непустые строки допустимы, пока правило не ограничивает их;
- ожидаемое и допустимые значения сравниваются без учёта регистра по умолчанию;
- для числовых параметров Revit диапазон проверяется в единицах отображения проекта;
- все заполненные ограничения одной строки применяются совместно.

## Привязка расширенных правил к элементам

В расширенном формате базовая привязка выполняется по `Category`. `Family` и `Type` уточняют выборку.
В каждом из трёх полей поддерживаются:

- точное значение: `Двери`;
- любое значение: `*`;
- маска: `Door-*`, `EI??`.

В матричном формате привязка выполняется по паре «имя параметра из A1 + значение из колонки A».

## Результаты

Окно содержит три вкладки:

1. `Правила` — нормализованные правила выбранного файла.
2. `Ошибки таблицы` — структурные ошибки и предупреждения до обращения к модели.
3. `Результат` — одна строка на неуспешное сочетание элемента и правила.

Для каждой ошибки показываются критичность, RuleId, модель/связь, ElementId, категория,
семейство, тип, параметр, фактическое значение, требование и пояснение. CSV-отчёт использует
UTF-8 с BOM и открывается в Excel.

## Ограничения и безопасность

- Поиск проверяемого параметра по имени зависит от языка Revit и становится ошибкой `AmbiguousParameter`, если у
  элемента найдено несколько одноимённых параметров. Для устойчивых корпоративных правил
  следует использовать GUID или BuiltInParameter.
- ElementId связанного элемента относится к связанному документу.
- Незагруженная связь показывается отдельным предупреждением и не проверяется.
- Если категория существует, но под маски Family/Type не попал ни один элемент, создаётся
  предупреждение `NoMatchingElements`.
- Live QA на реальном RVT обязателен: unit tests не подтверждают поведение конкретных
  корпоративных семейств, локализацию категорий и состояние связей.

## Рекомендуемая приёмка

1. Выбрать исходный XLSX или создать CSV из встроенного шаблона матрицы.
2. Указать в A1 параметр отбора, в колонке A — два его значения, в строке 1 — проверяемые параметры.
3. Поставить `+` в нескольких ячейках и подготовить элементы с заполненным, пустым и отсутствующим параметром.
4. Проверить итоговые количества и каждую строку результата по ElementId.
5. Повторить проверку с загруженной и выгруженной RVT-связью.
6. Экспортировать CSV и проверить кириллицу, разделители и значения в Excel.
7. Выполнить замер на самой крупной ожидаемой модели перед утверждением релиза.
