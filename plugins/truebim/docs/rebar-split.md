# Разбить арматуру

Команда **TrueBIM → КР → Разбить арматуру** создаёт отдельный элемент Rebar для каждого существующего стержня обычного набора и удаляет исходный набор. Новые элементы получают новые ElementId.

## Область обработки

- **Выбранные элементы** — все выбранные обычные наборы, включая наборы одинаковых стержней. Если выделения нет, после окна настроек начинается выбор в модели.
- **Все наборы переменных стержней** — поиск во всём текущем документе, независимо от видимости на активном виде. Набор включается, если максимальная и минимальная фактические длины существующих стержней отличаются более чем на 0,1 мм. Длина учитывает крюки и изгибы.

Одиночные стержни, свободная форма, армирование по площади/траектории, арматурные контейнеры и RVT-связи не обрабатываются. Исключённые позиции набора не создаются заново. В Revit 2022+ учитываются индивидуальные перемещения стержней.

## Параметры и геометрия

Сохраняются исходные тип арматуры, форма, основание, крюки и доступные для записи значения параметров экземпляра: встроенные, общие и проектные. Общие параметры сопоставляются по GUID, остальные — по Definition, а не по отображаемому имени. Типовые параметры остаются на исходном типе и не изменяются.

Размеры формы берутся для конкретной позиции стержня. Количество, схема/шаг распределения, суммарная и предельные длины набора и системный номер арматуры не копируются: они должны соответствовать одиночному стержню. Пользовательские позиции и марки копируются.

Revit может притянуть вновь созданный стержень к защитному слою. Если геометрия отличается только общим переносом, команда восстанавливает положение. Форма, длина и положение проверяются до удаления исходника и после фиксации транзакции. Несовпадение геометрии отменяет операцию; «всё равно разбить» разрешает только потерю параметров, а не искажение арматуры.

## Ошибка переноса параметров

Окно перечисляет ID исходных проблемных наборов. Разворачиваемые подробности содержат названия параметров и причины ошибки.

- **Отмена** — откат всей операции, включая успешно обработанные наборы.
- **Пропустить** — проблемные наборы остаются без изменений, остальные разбиваются.
- **Всё равно разбить** — проблемные наборы тоже разбиваются с сохранением доступной части параметров.

Проверка выполняется также после пересчёта/Commit. Если сторонний updater меняет параметр при фиксации, действуют те же варианты. При выборе пропуска транзакционная группа откатывается и операция повторяется без проблемных наборов. Результат отменяется одним действием Undo.

## Аннотации

Галочка **«Сохранять аннотации»** включена по умолчанию. При её отключении команда не сканирует оформление проекта. Оформление, сохранённое самим Revit, не удаляется принудительно.

При включении команда пытается восстановить независимые марки, линейные размеры и мультиарматурные аннотации на прежних видах. Марка конкретного стержня связывается с соответствующим новым элементом; марка набора без указания позиции — с первым существующим стержнем. Мультиарматурная аннотация связывается со всеми новыми стержнями вместо исходного набора. Для линейных размеров проверяется геометрическое соответствие ссылок и сохранение значений.

Поддерживаемое оформление сначала сохраняется в снимке и удаляется внутри общей транзакции, затем восстанавливается со ссылками на новые стержни. При отмене исходное оформление полностью возвращается откатом.

Невосстановимое оформление не блокирует разбиение. После операции результат перечисляет ID и причины неподтверждённого переноса или потери оформления. Штатные сообщения Revit не подавляются; замечания также доступны в техническом журнале TrueBIM. При извлечении из группы снимок включает поддерживаемое оформление её остальных элементов, включая основы арматуры.

## Закрепление и группы — начиная с 0.2.42

Перед изменениями команда перечисляет наборы в группах: ID, закрепление, название и ID группы. Поле доступно для выделения и копирования (`Ctrl+A`, `Ctrl+C`). Пользователь выбирает:

- **Извлечь из группы и разбить** — разгруппировать затронутые экземпляры и необходимые родительские группы, затем разбить перечисленные наборы. Новые группы не создаются.
- **Пропустить обработку элементов** — оставить перечисленные наборы и их группы без изменений, разбить остальные наборы.
- **Отменить всю операцию** — никаких изменений; закрытие окна и Esc действуют так же.

Для оставшихся закреплённых наборов открывается отдельное окно: сохранить закрепление новых стержней, снять закрепление, пропустить проблемные элементы или отменить весь запуск. Выбор для групп не меняет закрепление автоматически. Если пропущен один выбранный набор внутри группы, остальные выбранные наборы этой группы тоже пропускаются, чтобы сохранить её без изменений.

Выбранный набор внутри группы сопоставляется с тем же членом всех экземпляров её типа по порядку `Group.GetMemberIds()`. Соответствующие наборы во всех экземплярах включаются в операцию и список ID предупреждения, даже если не были выделены. Остальные наборы того же типа группы не добавляются автоматически. Если состав экземпляров не позволяет надёжное сопоставление, операция отменяется до изменений.

Извлечение выполняется через `Group.UngroupMembers()` без копирования групп и смены их типов. Остальные элементы сохраняют свои ID, геометрию, основу, закрепление и доступные параметры, но выходят из разгруппированных групп. Незатронутые вложенные группы остаются группами. Перед фиксацией и после неё проверяется сохранность остальных элементов.

Если разгруппирование меняет форму или свойства остальных элементов и восстановить их не удалось, попытка полностью откатывается. Все обрабатываемые наборы внутри групп пропускаются, группы остаются без изменений, а остальные наборы обрабатываются отдельно. В результате указаны количество необработанных наборов, их ID и причина. Это может означать частичное выполнение даже после выбора «Извлечь из группы и разбить».

Разгруппирование и возможная потеря оформления указаны в окне до выбора действия. Присоединённые группы узлов не сохраняются как группы. Опция сохранения аннотаций переносит поддерживаемые марки, линейные размеры и мультиарматурные аннотации по соответствию исходных и новых элементов. Остальное оформление может быть потеряно; замечания перечисляются в результате.

После Commit проверяются геометрия, основание, выбранное закрепление и наличие/отсутствие группы. Несоответствие отменяет всю операцию. Ошибка переноса параметров вызывает прежний отдельный диалог; отмена и пропуск также откатывают изменения групп. Если пропускается проблемный набор в группе, пропускаются и соответствующие наборы остальных экземпляров типа. Штатные предупреждения Revit не подавляются.

## Реализация и проверка

- `Commands/RebarSplitCommand.cs` — выбор области, запуск, диалог ошибок параметров.
- `Modules/RebarSplit/Revit/RebarSplitService.cs` — транзакции, откат и повтор при пропуске.
- `RebarSplitGeometry.cs` — геометрия каждой позиции, создание и проверка одиночных стержней.
- `RebarSplitParameters.cs` — значения экземпляра и проверка переноса.
- `RebarSplitAnnotationSnapshot.cs` — снимок оформления до замены элементов и перенос отдельными субтранзакциями.
- `RebarSplitGroupExtraction.cs` — извлечение из групп и проверка сохранности остальных элементов.
- `RebarSplitElementMap.cs` — соответствие элементов и отдельных позиций стержней до и после обработки.
- `RebarSplitGroupScope.cs` — сопоставление наборов всех экземпляров типа группы и совместный пропуск.
- `UI/RebarSplitProtectionWindow.cs` — отдельные варианты для групп и закрепления, копируемые списки ID.

Тестовый стенд `tests/TrueBIM.Revit.RebarSplitHarness` запускается командой:

Для новой сборки Revit может потребовать ручную загрузку модуля. Скрипт удаляет только собственный временный `.addin` и закрывает только запущенный им процесс. JSON-результаты сохраняются в игнорируемом каталоге `plugins/truebim/test-results/rebar-split`.

### Статус проверки 19.10.2026

Финальный код собран для Revit 2021–2026. Прошли 49 целевых тестов политики отбора, состава ленты и иконок; тестовый стенд также компилируется. API Revit 2019–2020 в окружении отсутствует, эти сборки не проверены. Готовые сборки находятся в `dist/rebar-split/revit/<год>`; установленный экземпляр TrueBIM этой проверкой не обновляется.

В Revit 2022 прошли 10 сценариев: одинаковые и переменные стержни, гнутая форма, крюки, исключённые и перемещённые позиции, включённый и выключенный перенос марки, полный откат, пропуск проблемного набора и принудительное разбиение при потере параметра.

После исправления мультиарматурная аннотация пересоздаётся, но полный прогон стенда не подтвердил доступность ссылок её размера. Тест обычного линейного размера остановился при создании исходной геометрии. Стенд был переведён с фонового документа на открытый вид; следующий запуск выявил запрет синхронного переключения вида из Idling. Переключение заменено на RequestViewChange, однако успешный повтор двух сценариев ещё не получен. Перенос этих видов оформления нельзя считать гарантированным.

Сборки и тесты вне Revit не заменяют эту проверку. Стенд содержит 12 сценариев и считает запуск успешным только при прохождении всех двенадцати.

Установщик 0.2.27 подготовлен для Revit 2021–2026. Для передачи заказчику это сборка для приёмочной проверки с указанным выше ограничением аннотаций. Само разбиение, перенос значений и варианты отмены/пропуска подтверждены отдельными сценариями.

API: [геометрия отдельных стержней и существующие позиции набора](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Discipline_Specific_Functionality/Structural_Engineering/Structural_Model_Elements/Reinforcement/Revit_API_Revit_API_Developers_Guide_Discipline_Specific_Functionality_Structural_Engineering_Structural_Model_Elements_Reinforcement_Rebar_html.html). ### Исправление доступности и проверка модели 20.10.2026

В версии 0.2.30 устранена причина постоянно неактивной кнопки: из `RebarSplitCommandAvailability` удалена проверка временного состояния `Document.IsReadOnly`. Во время настоящего вызова `IExternalCommandAvailability` Revit 2022 возвращал `IsReadOnly = true` как при наличии выделения, так и без него. Старое условие возвращало `false`, исправленное — `true`. Команда доступна в открытом проекте; предварительное выделение не требуется. Документ семейства по-прежнему не поддерживается.

На локальной копии предоставленной модели `Тест_rvt22.rvt` проверены четыре сценария: выбранные наборы и все наборы с фактически различающимися длинами, каждый с сохранением аннотаций и без него. Все проверки разбиения, геометрии, количества, удаления исходных наборов и переноса параметров прошли. По выбору разбиты 9 наборов в 45 одиночных стержней; по разнице фактических длин — 4 набора в 20 стержней. Остальные 5 наборов имеют тип распределения VaryingLength, но фактически одинаковые длины и правильно не попадают во второй режим. Ошибок переноса параметров не зарегистрировано.

Оформление проверялось отдельно от успешности разбиения. При обработке всех 9 наборов с сохранением аннотаций число размеров уменьшилось с 2378 до 2376: два обычных размера не перенеслись из-за недоступных геометрических ссылок. В режиме 4 наборов с разными длинами количество размеров и мультиарматурных аннотаций не изменилось. Сохранение аннотаций остаётся операцией по возможности.

Все изменения модели откатились, файл на W: не изменён. Контрольная сумма SHA-256: `1BEB3BBA64381534C1DB3D64C6CD363D5282EFA126F0CFBDE1D686BC239112AF`.

Отчёт: `test-results/rebar-split/revit-2022-48c85712f00d47dba3626917a2ee37f7.json`. Повтор проверки другой модели: `scripts/test-rebar-split-2022.ps1 -ModelPath <полный-путь.rvt> -ShowViewer -AllowExistingRevit -TimeoutSeconds 1800`; исходный файл автоматически копируется в каталог результатов.

### Сохранение обычных размеров — 0.2.32

Исправлена потеря двух обычных размеров `2031028` и `2031090` в предоставленной модели. Их ссылки типа `NONE` не отдавали геометрию через `GetGeometryObjectFromReference`. Теперь команда находит соответствующую ссылку кривой в геометрии вида размера, сопоставляет её с геометрией нужного нового стержня и сохраняет исходную семантику ссылки. Числовые части стабильного представления не используются как индексы стержней.

Переносятся режим отображения равных сегментов и выноска. Для формулы `4×200=800` Revit запрещает отдельно задавать положение текста сегментов; команда проверяет `IsTextPositionAdjustable` перед переносом положения. Значение `AreReferencesAvailable = false` на закрытом виде само по себе не считается ошибкой: сохраняются проверки количества сегментов и измеренных значений.

На копии `Тест_rvt22.rvt` прошли все 8 сценариев: две области обработки с включённым и выключенным сохранением аннотаций, сначала с начального листа, затем с открытого вида размеров. При разбиении 9 наборов в 45 стержней с сохранением аннотаций оба обычных размера восстановлены, число размеров осталось **2378**. Проверены соответствие привязок новым стержням, значения сегментов, тип, линия размера, вид, текст и режим отображения. На открытом виде Revit подтвердил доступность ссылок обоих размеров. В режиме переменных длин получены 20 стержней из 4 наборов; геометрия и параметры прошли проверки во всех сценариях.

Отчёт: `test-results/rebar-split/revit-2022-7d66faacb7274631b462c124e56f3feb.json`. Исходный файл не изменён. Проверка закрытого и открытого вида входит в режим `-ModelPath`; ключ `-SkipAvailabilityCheck` позволяет пропустить уже выполненную проверку доступности кнопки.

Это подтверждает исправление двух размеров данной модели. Сохранение остальных видов оформления по-прежнему выполняется по возможности; количество восстановленных мультиарматурных аннотаций не заменяет проверку всех их ссылок.

### Защита закрепления и групп — 0.2.41

Предыдущее предположение о штатном предупреждении Revit было неверным для API: в документации `Document.Delete` прямо указано, что закреплённые элементы удаляются без предупреждения. Явного открепления в команде не было, но результат всё равно нарушал требование сохранить защищённые элементы.

Команда проверяет обрабатываемые наборы до начала изменений и повторно перед удалением каждого исходника. Если набор закреплён или входит в группу, Revit показывает своё встроенное предупреждение, операция целиком отменяется. Даже обычные наборы из того же запуска остаются без изменений. Принудительное разбиение при потере параметров не отменяет эту защиту. Отдельный отчёт по статусам и автоматические манипуляции с группами/закреплением не добавлялись.

Целевая проверка в отдельном Revit 2022:

```powershell
.\plugins\truebim\scripts\test-rebar-split-2022.ps1 -ProtectionOnly -AllowExistingRevit -TimeoutSeconds 300
```

18 сценариев проверяют обычную арматуру, закреплённый набор, группу, несколько экземпляров группы, закреплённую группу и смешанный выбор при обоих состояниях галочки аннотаций. Для отклонённых операций сравниваются встроенные ID ошибок Revit, ID проблемных элементов, геометрия, параметры, закрепление и состав групп; для обычной арматуры проверяется успешное разбиение. Только тестовый стенд перехватывает ошибки для автоматического отката; рабочая команда их не подавляет. Для ручной проверки штатного диалога используется `-NativeDialogScenario Pinned` или `-NativeDialogScenario Grouped`.

Режим `-ModelPath` дополнительно проверяет отклонение операций с защищёнными наборами без изменения документа и отдельный выбор только незакреплённых наборов вне групп. Модель автоматически копируется, все тестовые изменения откатываются. Полный режим синтетического стенда включает 30 сценариев, режим `-ModelPath` — 12. Подробности текущего выпуска: [отчёт](rebar-split-protection-2026-10-21.md).

### Выбор обработки закрепления и групп — 0.2.42

Поведение 0.2.41 заменено отдельными окнами для групп и закрепления.
Для групп доступны извлечение, пропуск и отмена; для закрепления — сохранение,
снятие, пропуск и отмена. Список ID выделяется и копируется.
Итоговая проверка копии пользовательской модели в Revit 2022: 36/36 сценариев,
включая 8 сценариев безопасного частичного выполнения с уведомлением.
Подробности: [отчёт 0.2.42](rebar-split-actions-2026-10-21.md).

Текущий целевой стенд `-ProtectionOnly` содержит 140 сценариев, расширенный
`-Comprehensive` — 176, режим `-ModelPath` — 36. Полный синтетический прогон
новой реализации не подтверждён; результаты прежнего алгоритма групп к ней не относятся.
Исторический переключатель `-NativeDialogScenario`
удалён, поскольку команда больше не отклоняет защищённые наборы автоматически.
