Подтверждено ответами:

- Целевая версия — Revit 2023.
- Электрические цепи не используются. Основной ключ сопоставления — параметр «Группа» у потребителя и элемента схемы. По ответу заказчика номера не повторяются между щитами.
- Обозначения `1.4с` и `Гр.1.4с` эквивалентны; латинская `c` и кириллическая `с` эквивалентны. Префикс на схеме добавляется автоматически.
- Источник суммы — расчётная мощность каждого потребителя. Простое сложение, без коэффициентов. Контрольный пример: 1 + 3 + 4 = 8. Дополнительное умножение на количество ответами не задано.
- Пользователь уточнил масштаб: **1000 Вт у потребителей → 1 В·А в параметре схемы**. Следовательно, сумма мощности в ваттах делится на 1000, затем полученное число записывается как значение в В·А целевого параметра. Это специальное соглашение семейства, а не физический перевод Вт в В·А. Прямое уточнение заменяет буквальное прочтение «Вт = В·А» из анкеты. Внутренние значения Revit необходимо переводить через API единиц на обоих концах, а не копировать напрямую.
- Поиск источников — во всём активном RVT. Пользователь прямо исключил RVT-связи.
- Одна группа должна иметь один элемент схемы; копии являются ошибкой.
- Обновляются два поля схемы: суммарная мощность и «Потребитель». Несколько наименований соединяются через запятую. Пример заказчика: `1`, `2.4`, `Р.С.` → `1,2.4, Р.С.`. Пользователь подтвердил, что одинаковые наименования записываются один раз. Это не отменяет суммирование мощности каждого отдельного потребителя с таким наименованием.
- Пользователь выделяет нужные группы на схеме и запускает отдельную кнопку. Только выделенные группы перезаписываются; постоянное автоматическое обновление не требуется.
- При ошибке группа пропускается, после выполнения выводится предупреждение. Элементы без группы должны попадать в ошибки.
- Ноль и отсутствие данных заказчик предлагает считать нулём. Границы этого правила требуют уточнения, поскольку отсутствие группы отдельно названо ошибкой.
- На уточнение о группе без потребителей пользователь ответил: **пропустить и выдать предупреждение**. Такую группу нельзя обнулять или очищать при обновлении.

Предлагаемые технические решения, не являющиеся дословными ответами:

- Применять нормализацию группы только для сравнения, исходный текст параметров не менять. Дополнительно убирать крайние пробелы; удаление внутренних пробелов и нормализация других букв не согласованы.
- Искать дубликаты среди элементов семейств схемы во всей согласованной области, включая невыбранные копии. Блокировать запись только затронутых выбранных групп.
- Исключать элементы схемы из источников суммы, чтобы повторный запуск не прибавлял предыдущий итог.
- Считать экземпляр потребителя один раз, независимо от количества видов, где он показан. Правило для вложенных элементов определить по семействам.

- Записывать мощность и наименование группы согласованно; при невозможности записи одного поля не оставлять группу частично обновлённой. Пропущенные группы сохраняют прежние значения и явно перечисляются в отчёте.
