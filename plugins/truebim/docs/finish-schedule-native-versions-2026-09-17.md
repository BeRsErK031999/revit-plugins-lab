# Ведомость отделки: связь строк с помещениями

## Причина и требование

Исходное ТЗ требует обычную спецификацию категории «Помещения» ([ROADMAP](../../../docs/FinishSchedule/ROADMAP.md), раздел «Цель», пункт 7). Дополнительное требование — создавать новый выпуск при каждом запуске и сохранять значения предыдущих выпусков. Замена строк помещений статическими текстовыми ячейками не была требованием: это ошибка выбранной реализации сохранения версий.

В версиях 0.2.15–0.2.18 `FinishScheduleSnapshotService.Freeze` переносил данные в заголовок таблицы и исключал помещения фильтрами. Поэтому после работы плагина невозможно было выбрать помещение через строку ведомости, в том числе у прежней ведомости, которую плагин архивировал.

## Поведение 0.2.19

- Каждый выпуск остаётся обычной спецификацией помещений с данными в `SectionType.Body`. Строки связаны с реальными помещениями модели.
- Для каждого выпуска создаются отдельные текстовые параметры помещений: один на отображаемый столбец и один для состава выпуска. Например, ведомость из восьми столбцов добавляет девять параметров. Параметры выпуска доступны для чтения, изменение через интерфейс Revit запрещено.
- Новый расчёт обновляет выходные параметры и создаёт новую именованную версию. Значения уже выпущенных версий не перезаписываются. Новые помещения не попадают в прежний выпуск.
- Состав нового выпуска определяется точным набором ID помещений из расчёта. Посторонние помещения с заполненным примечанием не попадают в ведомость.
- Прежние управляемые ведомости переводятся в новый формат до записи новых расчётных значений. Сохраняются ID вида, имя, отображаемые значения и размещение на листах.
- Текстовые архивы восстанавливаются по уникальным номерам существующих помещений. Неизвестный, повторяющийся или неоднозначный номер, включая первую строку, блокирует операцию с пояснением. Архивы по именам или изменённым номерам нельзя надёжно восстановить автоматически.
- Все изменения входят в общую группу транзакций. Ошибка проверки состава или текста отменяет выпуск целиком, включая новые параметры. Путь общего файла параметров Revit восстанавливается после операции.

Это сохранение значений выпуска, а не резервная копия геометрии. Удаление исходных помещений или изменение их доступности в фазе/варианте проекта может повлиять на строки обычной спецификации. Удаление вида не удаляет автоматически его параметры выпуска.

- новая ведомость содержит ровно **54** помещения области расчёта; значения потолков `179,93` и `401,00` находятся в обычных ячейках тела;
- после изменения исходных параметров и добавления помещения прежние значения и состав сохраняются, следующий выпуск получает обновления;
- сохраняется размещение на листе, проходят стандартный режим шапки и режим без шапки;
- неоднозначное восстановление блокируется; откат удаляет временные виды и привязки параметров;
- выгрузка настоящей ведомости на лист просмотрена: многострочные значения видны.

## Проверка установленного плагина после перезапуска

Revit 2023 запущен повторно. По явному разрешению пользователя выбрана однократная загрузка TrueBIM. Та же модель открыта с отсоединением от хранилища и сохранением структуры рабочих наборов; открыт набор `10_АР`.

Через интерфейс `TrueBIM → Ведомость отделки` выполнены предпросмотр и два выпуска:

- Предпросмотр: 54 помещения, 30 групп, 520 стен, 52 пола, 114 потолков; 686 назначений. В плане записи нет блокирующих ошибок.
- Первый выпуск `Помещения • Ведомость отделки помещений 12357756`, ID `3147944`: записано 340 значений. Исходная управляемая ведомость преобразована с сохранением прежних значений.
- В новой ведомости выбрана строка `101`, затем нажата команда «Выделить в модели». Revit открыл план и выделил настоящее помещение с номером `101`; панель свойств показывает «Помещения (1)».
- В прежней ведомости выбрана строка `001, 201, 202, 203`. Команда «Выделить в модели» выделила четыре помещения; панель свойств показывает «Помещения (4)». Прежние значения, например `201,36` в первой группе стен, сохранены.
- Повторный выпуск создал отдельный вид `Помещения • Ведомость отделки помещений 12357756 (2)`, ID `3147973`. План содержит `RoomChanges=0`, запись — `RoomValues=0`. Оба предыдущих вида остались в диспетчере.

Ошибок уровня `ERROR` в журнале этого прогона нет. Сохраняются 26 предупреждений расчёта геометрии, включая контакты с несколькими помещениями и ошибки пересечения отдельных тел; данная проверка не снимает ранее описанные ограничения расчёта.
